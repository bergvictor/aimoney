## 1. What this project is and how it runs

- Purpose: AIMoney Lab — a ranked ledger of AI-money opportunities with research briefs, experiments, and a cron research agent that proposes/refreshes rows; the human vets, tests, kills/scales.
- Entry points: `public/index.html` + `public/app.js` (dashboard); `functions/api/[[path]].js` (REST API on D1); `worker/src/index.js` (research agent: cron + `POST /run` + `GET /`).
- Live surfaces: `https://aimoney.pages.dev`, `https://aimoney.pages.dev/api/health`, worker `https://aimoney-research.levitinvlad.workers.dev/` (see `deploy/public-surfaces.json`).
- Scheduled jobs: worker cron `0 */6 * * *` (`worker/wrangler.toml:9`); each tick collects signals, triages (≤6), inserts ≤2 proposals, briefs 1–2 bare rows.
- Deploy: Pages Git-connected (`public/`, stamped by `scripts/stamp-release.sh`); worker + D1 migrations via `deploy/deploy.sh` or `.github/workflows/deploy-worker.yml`; gated by `deploy/verify.sh`.

## 2. End-to-end walk-through

Main flow A — signal → proposal → vetting → experiment → decision (the lane-metric path):

1. Cron tick opens a run row (`worker/src/index.js:361-370`) and collects HN/Reddit/GitHub signals in parallel (`:386`, collectors `:49`/`:81`/`:110`), inserting them in one batch (`:397-402`).
2. Stale unprocessed signals >30d are swept to noise (`:414-415`); the 6 oldest unprocessed are taken (`:420-422`); exact-URL duplicates pre-link as supports without an AI call (`:434-461`).
3. Inflow gates read bare-without-brief and unreviewed counts (`:476-483`); while unreviewed > 10, inserts cap to 0 and the tick skips the classify AI call entirely (`:494-506`), logging `inflow:paused`.
4. Otherwise one Mistral classify call triages the 6 (`buildClassifyPrompt` `:315`, `parseJsonLines` `worker/src/lib.js:64`); verdicts write as one batch with per-write fallback (`:520-599`, `flushVerdictWrites` `:334`).
5. Cron ticks brief 1 bare row (top-scored, or oldest-unreviewed-first past 48h) plus 1 extra oldest-unreviewed past 48h (`:621-713`; prompt `:208`, parse `:219`, guarded insert `:230`); manual `POST /run` always skips briefs (`:381-384`, `:795-806` returns 202 + `briefs_skipped:true`).
6. Human vets in the dashboard: review chip lists oldest-first (`public/app.js` review filter; `GET /api/opportunities?unreviewed=1&sort=oldest` served by `functions/api/[[path]].js:148-190`); `V` vets / `K` kills; Vet PATCHes notes with a `[YYYY-MM-DD vetted]` tag (`public/app.js:587-592`, tag builder `:501-510`); the API rejects tagless clears and post-mortem-less kills with 400s (`functions/api/[[path]].js:276-293`).
7. `Vet & log starter` composes Vet + planned-experiment POST + status→testing in one tap with planned-starter resume (`public/app.js:653-670`, resume `:624-639`); Start/Win/Lose close the loop (`:863`, `:914`, `:880`); closes require result + post-mortem and stamp `ended_at` (`functions/api/[[path]].js:394-404`, `:473-479`), appending a one-line `$X rev / $Y spent` outcome to the parent notes (`outcomeLedgerLine` `:108-113`, appended `:436-442`/`:483-489`).
8. `/api/health` reports the lane numbers from one batched probe set with per-probe isolation fallback (`functions/api/[[path]].js:531-714`); the dashboard week line + stall nudge render from it with null-guards (`public/app.js:935-974`).

Where it most often breaks or goes silent (live evidence): the human verdict step. `unreviewed=15` oldest 12.7d with `last_verdict=null` means no verdict was ever recorded, so gate (3) holds every tick at `inflow:paused` and the funnel only briefs. ## 5. What NOT to change

- Default-off migration gate — deliberate: "Default-off: unset changes nothing; the health payload then names the missing columns plus the disabled line." (`functions/api/[[path]].js:23-24`; `README.md:83`; `docs/OWNER-ACTIONS.md` §2). The owner flips it; code must not self-migrate without the var.
- Agent proposes, human disposes — deliberate: "The agent PROPOSES; the human owns the testing workflow (it never moves status to testing/scaling/killed)." (`worker/src/index.js:4-5`; `README.md:72` "The agent never moves status"). No auto-transitions, no bulk verdicts ("one human verdict per keypress, no bulk path", `README.md:71`).
- Manual `Run triage now` skips briefs — deliberate: "The manual path shares waitUntil's 30s cap …, so it runs collect+classify only" (`worker/src/index.js:381-384`); briefs land on cron ticks.
- Killed rows stay listed with their post-mortem ("Killed strategies stay on the board with their post-mortem — that is the point.", `README.md:64`); closes require result + post-mortem; outcome ledger never touches the score and rescore is "never auto-applied" (`README.md:74`).
- Received-only revenue semantics ("only money actually received goes here, since every recorded cent counts toward lifetime revenue", `README.md:74`); never invent `$` figures, reviews, or testimonials.
- `public/release.json` reads `{"revision":"dev-undeployed"}` in the repo — stamped at build by `scripts/stamp-release.sh`; do not hand-edit it.
- Owner-only one-liners (needs a login, credential, or human decision — not implementer tasks): set `ALLOW_SCHEMA_MIGRATION=1` on the Pages project and retry the deployment; add `CF_API_TOKEN`/`CF_ACCOUNT_ID` repo secrets and redeploy (or run `deploy/deploy.sh`) for the `revenue_source` column; clear Needs-review with `V`/`K` (or Vet / Vet-&-starter / Kill); press `Vet & log starter` → `Start` → `Win`/`Lose` on the `$0` starter within a week.
